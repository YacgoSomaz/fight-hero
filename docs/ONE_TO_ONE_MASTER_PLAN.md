# 《战火英雄》网页 1:1 复刻总目标与实施计划

更新时间：2026-07-22。本文定义最终目标，不以“能打开”“能走路”或“画面相似”替代完成。

## 1. 最终目标

在本地网页运行环境中，基于已解包原 SWF 的素材、Display List、时间轴、AS3/P-code、地图节点和规则数据，复刻用户能实际玩到的原版体验。完成时应满足：

1. 任何已显示的图像、音频、动画和 UI 均可追溯到原 SWF 导出或其原始运行时关系；不以手绘、临时 CSS 图形或“看起来差不多”的替代物填补原始内容。
2. 菜单、关卡、模式、角色、武器、AI、物理、HUD、任务推进和存档的行为有原始 AS3/时间轴/节点证据，且网页行为与之对照验收。
3. 每个完成项都同时具备：原始证据位置、网页实现位置、自动测试、人工对照截图或输入回放结果。
4. 未迁移、证据不足或未对照的部分必须明确标注为未完成；绝不能用“可运行”或“私用”将其称作 1:1。

## 2. 证据优先级

发生冲突时按下列顺序取证：

1. 原 SWF 运行结果和原版可录制画面；
2. 原 SWF 的 AS3、P-code、时间轴标签、Place/Remove Display List；
3. FFDec 直接导出的 symbol、位图、声音、节点和矩阵；
4. `assets/reverse/` 与 `private-assets/` 中保留的解析报告；
5. 现有网页代码和测试。

网页代码不是原始行为的证据。若原件尚未找到，工作项应留在“待解包/待验证”，而不是自行补写一个相似机制。

## 3. 子系统实施清单

### A. 证据台账（第一优先级）

为下列每个实体建立一行台账：`原始 symbol/AS3 入口 → 导出资源/数据 → 网页模块 → 自动测试 → 原版对照截图 → 状态`。

- 菜单帧、按钮命中区、标签页、锁定/解锁状态；
- 14 个地图视觉 ID、地图物理 ID、昼夜变体、三层图像和 wallMC；
- UnitMC、各兵种皮肤、HUD、准心、血条、弹药、经验条；
- `Stats_Guns` 的每一把枪、枪械子时间轴和声音；
- `Stats_Campaign`、挑战目录、任务和胜利/失败条件；
- `Movement`、`AI`、`Arena`、`Unit`、`MatchSettings` 的关键函数与数据关系。

完成标准：每个已经向用户开放的功能都有完整台账；台账缺口会阻止其被标成完成。

### B. 原始菜单与全部入口

范围：Home、Play、Soldiers、Options、Medals、Tips、Version、Campaign、Challenges、Quick Match。

- 必须复用原始菜单帧，而非重新设计一个前端菜单；
- 每个可见按钮必须对应 Menu.as 的真实 action、坐标和状态变化；
- Soldiers/Options/Medals/Tips/Version 不能仅是无效按钮；若未解出行为则必须继续解包；
- 战役 15 项、挑战 15 项、快速对战的地图/模式/分数/士兵限制/技能/连杀/难度循环必须一致；
- 菜单音乐、点击音、存档读取、解锁状态和返回路径必须可验证。

验收：逐页原版与网页并排截图；对每一个可见按钮进行一次点击回放并记录目的状态。

### C. 全部地图、镜头和物理数据

地图范围：`tut`、`foundry`、`foundry2`、`train`、`train2`、`plane`、`plane2`、`swamp`、`swamp2`、`cave`、`cave2`、`dropship`、`missile`、`missile2`。

每张地图必须完成：

- `BgSky`、`Bg`、`Arena` 图层的原始裁切、注册点、缩放、遮挡顺序和镜头滚动；
- Arena 的 `wallMC` 或 `NodePhysBox` 碰撞，禁止用通用地板取代；
- 出生点、waypoint、action（跳跃/攀爬等）、pickup、CTF 旗帜、DOM 占领点；
- 昼夜变体只改原版实际改变的层，不复制出一套脱节物理；
- 从边缘、坑、上坡、下坡、平台底部、攀爬边沿逐项验证玩家和 AI。

验收：每图至少覆盖出生、连续移动、跳跃、攀爬、坠坑、敌人追击、镜头边界和对应模式目标的输入回放。

### D. 角色、动画、瞄准和 HUD

- UnitMC 必须按原 Display List 和帧标签播放：待机、跑、倒跑、跳、坠落、蹲、起身、蹲走、攀爬、重落地、受击、死亡、复活；
- 头、躯干、双臂、双腿和枪械的 holder/matrix 必须保留，鼠标只驱动原版会驱动的部件；
- 所有兵种皮肤、随机角色逻辑和可选兵种须来自原资料；
- 头顶血条、底部职业/生命/等级/经验、弹匣、备用弹药、准心、命中反馈必须复用原 HUD symbol；
- Canvas 合成不可靠时，可用 DOM 承载原始图像，但其坐标、遮挡、翻转和状态必须与单位/镜头同步。

验收：逐动作帧与原版截图对照；移动、反向瞄准、左键开火、换弹、贴墙蹲起、自动攀爬和复活均须人工回放。

### E. 武器、战斗、音效和特效

- 将 `Stats_Guns.addGun` 的完整武器定义导入可查询数据表；
- 每枪实现原始弹匣、备用弹药、射速、后坐、散布、射程、伤害、换弹和子时间轴；
- 枪口、弹道、命中、爆炸、掉落、拾取、音效和粒子从原素材/代码取值；
- 不得只用 M4 的固定演示替代完整枪表。

验收：按武器表生成回归用例；关键枪械逐帧对照开火与换弹，全部枪械至少验证可装备、可开火、可换弹和伤害规则。

### F. AI、运动和五种对战规则

- Movement：脚底/头顶/侧向探针、坡面、小/大攀爬、贴墙蹲起、重力、平台和子弹墙体碰撞；
- AI：索敌、视线、瞄准平滑、开火概率、waypoint 图搜索、action 框、跳跃、脱困、随机配置；
- 规则：Deathmatch、Team Deathmatch、Capture the Flag、Domination、Juggernaut 的出生、计分、旗帜、占领、角色转换、胜利和结束；
- 战役/挑战：每关的敌人/任务/解锁/失败/结算，而不是将目录项全部折叠成同一个死亡竞赛。

验收：每条 AS3 分支至少映射一个单元/集成测试；每个模式由真实输入回放到得分或结束状态。

## 4. 质量门槛

每次提交涉及上述系统时：

1. 先新增针对原版行为的 RED 测试；
2. 采用原始资源或证据实现最小修复；
3. 跑 `npm test` 和 `npm run test:coverage`；
4. 对可视变更做浏览器截图/输入回放；
5. 更新台账、解包报告和交接文档；
6. 只有全部证据齐全的项目才可标为完成。

## 5. 当前状态与下一步

当前已有菜单帧、部分地图资源/节点、Foundry 物理基础、部分 UnitMC 时间轴和 M4 关系；它们是素材与数据基线，**不是 1:1 完成声明**。

当前最近的阻断点是运行时 Canvas 在部分环境被 DOM 地图层合成遮挡。因此先用原 UnitMC 完整 Medic 素材建立了同坐标 DOM 角色覆盖层，保证角色可见；下一步仍要把实时 HUD、头顶血条、完整部件动作和枪械状态放进同样可见、可对照的层，并补回 Canvas/DOM 的统一渲染契约。
