# 《战火英雄》1:1 网页迁移执行登记册

更新时间：2026-07-22。本文把[总计划](ONE_TO_ONE_MASTER_PLAN.md)拆成可停止、可交接、可逐项验收的工作包。它不是效果愿望清单：每一项只有在“原始证据 → 运行时承载 → 自动回归 → 原版实机对照”全部闭环后才可记为完成。

## 1. 目标、范围与完成口径

### 1.1 最终目标

在浏览器的原 SWF 舞台规格（800×600、30 FPS）内，使用户可从原始主菜单进入原有 Campaign、Challenges 和 Quick Match，选择原有角色/武器/设置，并在 14 张原地图和 5 种原规则下获得与 SWF 一致的画面、输入响应、物理、AI、HUD、声音、结算和本地进度体验。

“1:1”不是单项视觉相似，而是下列五层同时成立：

| 层 | 必须相同的内容 | 允许的网页技术差异 | 不允许的替代 |
| --- | --- | --- | --- |
| 资源 | 角色、地图、UI、声音、字体均来自已授权原 SWF 导出 | Canvas / DOM / WebAudio 的承载方式不同 | 手画精灵、CSS 图标、网络随意找图、拿用户截图当游戏素材 |
| 数据 | 数值、标签、地图节点、碰撞掩码、菜单参数来自 AS3/时间轴 | 数据可转为 JSON/模块 | 估算数值、将一个 M4 演示复制成全部枪械 |
| 状态 | 输入、动作、动画、HUD、模式进程的状态转移可追溯到 AS3 | 可采用确定性 JS 状态机 | “能动”就算完成、定时切图代替状态机 |
| 表现 | 坐标、注册点、层级、方向、裁切、镜头和动态文字对照原版 | 可为浏览器 DPR 做等比外层缩放 | 16:9 拉伸、错层、跳屏、整张 PNG 轮播代替肢体动画 |
| 验证 | 同输入的自动回归和原版实机截图/录屏均留下证据 | 允许记录已知差异 | 没有跑过就称“修好”、只测资源存在 |

### 1.2 当前边界

- 当前仓库已具备可启动的**迁移验证基线**，不具备完整原版游戏资格。
- 当前已使用的原资源、SWF 和导出物只在本项目已授权范围内处理；任何公开发布前都要重新确认权利范围。
- 当前不做公网联机。联机必须在单机行为、帧时序、物理和模式规则经原版对照后另开工作包；它不能作为当前行为偏差的借口。
- 未有原版证据的事项只能标“待解包”或“待采样”，不能用自写前端填空后标为完成。

## 2. 每个工作项的强制记录格式

每项 PR/提交/交接记录必须填写这八格；缺任一格，状态只能是“进行中”。

| 字段 | 必须写什么 |
| --- | --- |
| 目标对象 | 精确到 symbol、类、函数、帧标签、地图 ID 或规则名，例如 `Hud 1477.bar_exp` |
| 原始证据 | SWF 路径、AS3 函数、frame/depth、FFDec 导出命令、原版采样文件之一或多个 |
| 已确认事实 | 只写已经读到/测到的矩阵、数值、逻辑分支；推测必须单列为推测 |
| 网页边界 | 哪些 `src/` 和 `public/` 文件允许改，哪些相邻系统本次不动 |
| RED | 新增测试名称、旧版本失败原因、RED 提交号 |
| GREEN | 实现文件、GREEN 提交号、为何不引入替代素材/规则 |
| 验收 | 全量测试、覆盖率、输入步骤、原版对照截图/录屏文件、已知差异 |
| 后续 | 下一步依赖、不能跳过的阻断点和不应误报的结论 |

状态只允许使用：`未开始`、`解包中`、`已定位`、`RED 已提交`、`GREEN 待实机`、`已实机对照`、`完成`、`阻断`。禁止使用“差不多完成”“基本可玩”“应该没问题”。

## 3. 依赖图与阶段门

```text
SWF 基线/导出可复现
        ↓
证据台账 ──→ HUD 1540 ──→ UnitMC + M4 动作闭环
        ↓                              ↓
14 图的视觉层/墙体/节点 ─────────→ Foundry 物理基准
                                         ↓
                           AI 路径/动作框/脱困
                                         ↓
          菜单/武器表/模式/战役挑战 ──→ 全量逐项验收
                                         ↓
                         发布前差异清单与交接
```

阶段门的含义是依赖关系，不是“先后随意”。例如：

1. 未确认 `wallMC`，不能把可见背景的边缘当作碰撞；
2. 未确认 UnitMC 的子部件矩阵，不能靠整帧角色 PNG 宣称跑步/攀爬已迁移；
3. 未确认 `Stats_Guns`/`Guns` 数据与动画，不能用一个固定 M4 代替武器系统；
4. 未确认地图 action 节点与 AI 行为分支，不能用直线追人或传送脱困代替原版导航；
5. 未逐关读取 `Stats_Campaign.runScripts(Game)`，不能将目录可点击说成战役已完成。

## 4. 详细工作包

### WP-00：原始基线、工具链与对照集

| 项 | 工作 | 原始依据 / 产物 | 退出条件 |

## 6. 变更前检查清单

- [ ] 这次功能的原 symbol/class/frame/function 已定位，且文件路径写入台账？
- [ ] 新增 RED 测试已在旧代码失败并单独提交？
- [ ] 运行时直接使用原导出资源/原数据，而不是自画/估算回退？

- [ ] `npm test` 与 `npm run test:coverage` 都通过，且覆盖率不低于门槛？
- [ ] 有实际浏览器输入回放或明确记录为什么当前无法采样？

- [ ] Git 提交说明了原始依据和功能边界，没有把局部成果称为全量 1:1？

任一项为“否”时，改动只能保留在研究分支或标为进行中；不得交给用户说“已经修好”。
